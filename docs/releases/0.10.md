# 皮友助手 0.10
## 本次更新
- 适配皮皮虾 6.6.0（versionCode 660）。
- 关于页适配版本列表加入 6.6.0，`CACHE_NAME` 升级为 `.cache660v1`，让旧版本的探测缓存自动失效并重新解析宿主类名。
- 功能与适配范围沿用 0.0.9，并同时兼容 6.5.5、6.5.0、6.2.0。
## 适配验证
以 6.6.0 原包（`com.sup.android.superb`，112,955,814 字节，35 个 dex，131 个 arm64-v8a so，未加壳）构建 dex 离线索引，共 105,999 个类，逐项核对模块对宿主的所有引用：
- 31 处字面量 hook 调用点：类名、方法名、参数表签名逐项比对，全部命中。
- 23 项 `Init.cache` 动态变量型映射（`class_*` / `method_*` 探测键）：反射探测结果对应的类与方法全部存在，0 缺失。
- 30 余个反射探测函数（`findClassCompat` 系列、字段与方法特征匹配）：离线复现判定逻辑，46 项判定全部命中。
- 全部硬编码类名：117 处解析成功；38 处未解析项均为 `findClassCompat(新名, 旧名)` 中的旧版 fallback 名，主名在 6.6.0 中均存在，属预期且无害。

结论：`Init.kt` 的反射探测机制对 6.6.0 完全兼容，本次无需改动任何 hook 逻辑，仅更新版本展示与缓存名。
## 验证
真机（LSPosed IT 2.1.0-it，API 102）对 6.6.0 原包冷启动冒烟测试：
- 模块正常注入，`Entry run hook` 日志 114 条，assist / misc / purity 三组 hook 类全量执行。
- 无 `FATAL EXCEPTION`、无 AndroidRuntime 崩溃、无模块 E/W 级错误日志。
- `VideoHook resolve cache helper=com.sup.android.video.g config=com.sup.android.video.f gate=b` 等缓存探测均命中。
- 新缓存文件 `/data/data/com.sup.android.superb/cache/.cache660v1` 正常生成，旧 `.cache620v2` 不再写入。
- `:app:testDebugUnitTest` 与 `:app:assembleRelease`（R8 minify 与 shrinkResources）构建通过。
## 使用说明
更新后强行停止皮皮虾再打开即可，无需重启手机。适配皮皮虾 6.6.0、6.5.5、6.5.0、6.2.0。应用内检查更新读取 LSPosed 收录仓库的 Release。
包名 io.github.vs2pk0.piyou，内部版本号 20261029，可覆盖安装旧版模块；本次不是 LSPatch 集成包。
